### 1. Internet Protocol Version 8 (IPv8)
Предложенный протокол следующего поколения с 64-битной адресацией, объединяющий DHCP8, DNS8, NTP8 и OAuth2 JWT-аутентификацию в единой платформе Zone Server с полной обратной совместимостью с IPv4.
**Link:** https://www.ietf.org/archive/id/draft-thain-ipv8-00.html
**Talking Points:**
- Формат адресации r.r.r.r.n.n.n.n, где префикс — это ASN: насколько это реалистичная модель для глобального интернета и что это меняет для операторов сетей?
- Ограничение таблицы BGP8 одной записью на ASN звучит революционно — это решение проблемы роста таблиц маршрутизации или слишком жёсткое упрощение?
- IPv4 как подмножество IPv8 без двойного стека — мечта любого сетевого инженера, но насколько реальна миграция и есть ли у этого черновика шансы пройти через IETF?

### 2. Release v1.15.0 · hashicorp/terraform · GitHub
Terraform 1.15.0 добавляет поддержку переменных в атрибутах source и version модулей, атрибут `deprecated` для переменных и outputs, аутентификацию S3 через `aws login`, функцию `convert` и улучшенное тестирование с mock-блоками.
**Link:** https://github.com/hashicorp/terraform/releases/tag/v1.15.0
**Talking Points:**
- Переменные в `source` и `version` модулей — долгожданная фича: как это меняет подходы к организации модульных монорепозиториев и динамической конфигурации?
- Атрибут `deprecated` для переменных и outputs — это шаг к более зрелому API-контракту в инфраструктурном коде: насколько это важно для больших команд?
- Сборки для Windows ARM64 и улучшения SSH-провизионеров — Terraform всё ещё активно развивается, но достаточно ли этого на фоне разговоров о его смерти?

### 3. Terraform is dead | graham gilbert
Автор утверждает, что Terraform устарел: ИИ устраняет необходимость в HCL как промежуточном слое между замыслом и инфраструктурой, а Pulumi с реальным кодом становится более естественной альтернативой.
**Link:** https://grahamgilbert.com/blog/2026/04/20/terraform-is-dead/
**Talking Points:**
- Тезис об ИИ как замене DSL-слоя звучит провокационно — но действительно ли мы уже в точке, где диаграммы и естественный язык надёжно транслируются в инфраструктуру?
- Pulumi как альтернатива: реальный код, тестируемый и компонуемый — но не несёт ли это новые проблемы с порогом входа и сложностью для ops-команд без dev-бэкграунда?
- Инерция Terraform огромна: миллионы строк HCL в продакшене, экосистема провайдеров, Terragrunt — как долго «мёртвый» инструмент может оставаться стандартом индустрии?

### 4. Release v1.0.0 · gruntwork-io/terragrunt · GitHub
Terragrunt достиг версии 1.0.0 с гарантией стабильности API в минорных релизах, изменениями в работе кэша, удалением зависимости от tflint из-за лицензии BUSL и улучшенной совместимостью с Windows.
**Link:** https://github.com/gruntwork-io/terragrunt/releases/tag/v1.0.0
**Talking Points:**
- Версия 1.0.0 с гарантией отсутствия breaking changes в минорных релизах — что это означает для команд, которые давно используют Terragrunt в продакшене и боялись обновляться?
- Удаление зависимости от tflint из-за лицензии BUSL — ещё один эхо-сигнал от смены лицензии HashiCorp: насколько лицензионные риски теперь влияют на архитектурные решения в open-source экосистеме?
- Terragrunt 1.0.0 выходит на фоне разговоров о смерти Terraform — это ставка на долгосрочное будущее HCL-экосистемы или попытка зафиксировать зрелость перед закатом?

### 5. Release release-1.30.0 · nginx/nginx · GitHub
nginx 1.30.0 добавляет поддержку HTTP Early Hints, Multipath TCP, sticky-сессий для upstream, директиву max_headers, улучшения QUIC и совместимость с OpenSSL 4.0 и AWS-LC.
**Link:** https://github.com/nginx/nginx/releases/tag/release-1.30.0
**Talking Points:**
- HTTP Early Hints (103) и Multipath TCP в одном релизе — насколько эти фичи востребованы в реальных продакшен-сценариях и кто уже готов их использовать?
- Sticky-сессии для upstream наконец в ядре nginx — что это меняет для тех, кто держался на nginx Plus или сторонних модулях ради этой функциональности?
- Активная работа с QUIC, OpenSSL 4.0 и AWS-LC говорит о серьёзных инвестициях в будущее: как nginx позиционируется относительно Envoy и других современных прокси?

### 7. NORA — Lightweight Artifact Registry
NORA — лёгкий реестр артефактов на Rust: единый бинарник 32 МБ, менее 100 МБ RAM, поддержка Docker, Maven, npm, PyPI, Cargo, Go Modules, S3-хранилище, RBAC и Prometheus-метрики.
**Link:** https://github.com/getnora-io/nora
**Talking Points:**
- Единый бинарник 32 МБ против Nexus или JFrog Artifactory с их сотнями мегабайт и сложной настройкой — для каких сценариев NORA реально может заменить тяжёлые решения?
- Rust как основа для инфраструктурных инструментов становится трендом: что это даёт с точки зрения безопасности, производительности и доверия к инструменту в продакшене?
- SBOM, fuzz-тестирование и подписанные релизы из коробки — насколько важна supply chain security для реестра артефактов и задаёт ли NORA новую планку для этого класса инструментов?

### 8. agent-sandbox — Kubernetes SIG Apps
agent-sandbox вводит CRD Sandbox для управления изолированными stateful-воркло́дами в Kubernetes с поддержкой pause/resume, gVisor/Kata Containers и Python SDK. Ориентирован на AI-агентов и dev-среды.
**Link:** https://github.com/kubernetes-sigs/agent-sandbox
**Talking Points:**
- Новый примитив между Deployment и StatefulSet — действительно ли существующих абстракций Kubernetes не хватало для AI-агентов, или это симптом того, что Kubernetes пытается решить слишком много задач?
- Изоляция через gVisor и Kata Containers для AI-агентов — насколько это критично с точки зрения безопасности, когда агент может выполнять произвольный код?
- SandboxWarmPool и lifecycle-операции pause/resume — это звучит как управление дорогостоящими AI-рантаймами: как это соотносится с экономикой токенов из предыдущей новости?
